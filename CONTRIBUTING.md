# Contributing

Thanks for helping make workplace evidence inspectable and its contributors harder to identify.
Read the [product principles](docs/product-principles.md) and [threat model](docs/threat-model.md) first.

## Run the project

Use Node 26.5.0 (`.node-version`) and Bun 1.4.0. Node 24+ is required by the runtime dependencies;
CI uses the pinned version. Commands run from the repository root.

```sh
bun install --frozen-lockfile
npm run fonts
npm run prepare:local
npm run dev
```

Open http://localhost:8788. After browser/shared code changes, run `npm run build:local`.
Stop the three workers with `npm run dev:stop`. Logs and databases are under `.wrangler/`.
The launcher generates ignored `.local-*.wrangler.jsonc` files with the remote-only AI binding omitted.

No cloud credentials are needed for the local fixtures or the automated checks. An optional
`TYPESAFE_API_KEY` in `.env` enables hosted inference; `.env.example` documents it. With no key,
manual controls work, model-dependent checks report unavailable, and hosted quality evaluations
are not exercised. Local cryptographic secrets and keys are generated by `prepare:local`.

## Verification

```sh
npm run build:local
npm run typecheck
npm test
npm run check:licenses
npm run check:publication
```

For the full local-stack and browser suites, stop any existing local stack first:

```sh
bunx playwright install chromium
npm run test:stack
```

`test:stack` owns and stops its worker processes, refuses occupied ports, and runs integration
checks followed by Playwright. It selects the test-only inference entrypoint in `tests/inference-fixture.ts`:
the real screening route and policy validate deterministic provider answers for one exact synthetic
paragraph. All other inference stays unavailable; this does not measure model quality. The fixture
refuses non-development environments and is not used by normal `npm run dev` or production configs.
The contribution/browser harnesses use synthetic data and local cryptographic keys.
Hosted model evaluation (`npm run eval`) is an explicit, potentially billable
maintainer task, not a pull-request requirement.

## Propose and submit changes

- Open an issue for substantial architecture, protocol, moderation, or dependency changes before implementing them.
- Fork the repository, create a focused branch, and explain the behavior and verification in a pull request.
- Keep the existing TypeScript/ESM style and avoid unrelated formatting changes.
- Add regression coverage for behavioral changes, especially privacy, key separation, publication thresholds,
  and protocol invariants. Documentation-only edits do not need artificial tests.
- Use fictional employers and synthetic examples. Never attach production data, mailbox addresses, credentials,
  unpublished testimony, or someone else's identifying information to an issue, PR, log, or screenshot.
- Report vulnerabilities through [private reporting](SECURITY.md), rather than a public issue.

## Publication manifest and dependencies

`public-source.json` lists every approved repository file explicitly. The build embeds its text files
at `/api/source`; binary Open Graph images remain in GitHub and are embedded separately as images.
Adding a file locally cannot add it to the served source bundle automatically.

When adding or removing files, stage only the reviewed paths, then run:

```sh
node tools/publication.mjs --update
git diff -- public-source.json
git add public-source.json
npm run check:publication
gitleaks git --pre-commit --staged --redact --no-banner
```

Check the staged contents as well as filenames. Never force-add ignored files. The publication check
rejects private paths, symlinks, submodules, and unexpectedly large files. Gitleaks also runs in CI.

After changing dependencies, update `bun.lock` with Bun. For runtime dependency changes, run
`node tools/licenses.mjs --write`, review the license texts and `licenses/index.json`, remove obsolete
notice files, and include the updated publication manifest. Preserve upstream notices in releases.
CI also runs `bun audit --audit-level high` and a weekly check. Dependabot updates Actions; its Bun
lockfile-v2 parser limitation is tracked in [issue #8](https://github.com/eliseorobles/shouldiworkthere/issues/8).
